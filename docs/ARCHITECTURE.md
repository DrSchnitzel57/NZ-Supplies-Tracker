## Data and business rules

- Internal immutable IDs connect roster entries, items, issues, issue lines, movements and audit events. Missionary external IDs remain unique strings; item matching normalizes category/item/size. Renames do not rewrite past issue snapshots.
- Items can be archived/reactivated without losing balances or history. Archived records cannot receive new issues; historical reversals remain possible. Account deactivation invalidates active sessions.
- Opening balances, receipts, physical-count adjustments, issues and reversals are recorded movements. Remaining is authoritative from the ledger; Out is net recorded issuance, not arbitrary stock reductions. Display corrections separately so Stock/Out labels do not misrepresent losses or count changes.
- Never commit a negative available balance. Every submission rechecks availability; duplicate submissions have idempotency keys. A full issue either commits all accepted lines or none. On shortage, return an explicit revised proposal; staff confirm it, and the server rechecks again. Do not silently reduce quantities.
- Staff can reverse a complete issue once, with a reason; reversal restores stock, retains original lines and actor, and contributes correctly to net reports. No partial reversal in this first release.
- Forms use record/version checks to prevent stale edits or physical counts silently overwriting newer work. Concurrent writes, reset, imports and updates coordinate through maintenance/write guards.

## Identity and permissions

- Local accounts only. Administrators create users/reset temporary passwords; require a password change before application access. A documented host command recovers an administrator without exposing passwords in logs or command arguments.
- Staff manage routine rosters, items, adjustments, add/update imports, issuing/reversals and reports. Administrators additionally manage users, replacement imports, full bundles, full reset and system settings. Explicit permissions are checked on every server entrypoint.
- Secure cookie sessions, CSRF protection, password validation, bounded login throttling and no secrets in images/logs. Thirty minutes of user inactivity expires a session; background polling does not extend it. Sensitive admin actions require recent password reauthentication.
- Full reset requires typed confirmation, reauthentication, exclusive maintenance, and a verified backup. Empty operational tables only; preserve accounts and a protected reset audit marker. Do not recreate the seed automatically. Previous operational audit content is part of the backed-up data, not retained as a hidden live copy after reset.

### Issuing and recovery
- One workspace for main and profile-based issuing: explicitly selected missionary, searchable catalogue (item/category/size), consolidated item list, quantities and a clear named summary before submission. Allow at most 50 distinct items, visibly stated and enforced server-side without truncation. Repeated selections increase the same line; changing recipient requires confirmation and then clears items and note.
- Keep original requests while reviewing shortages, recheck at confirmation, and permit returning to edit without losing the draft. Validation, maintenance and connection failures explain whether success is confirmed; uncertain responses retain the idempotency key for a deliberate retry, never an automatic issue replay.
- Draft lifetime is the open tab only: preserve through errors and same-user sign-in recovery, warn before leaving, and discard on reload/close. No server-saved drafts, autosave, offline queue or personal browser storage. Reauthentication must refresh security tokens without submitting the draft automatically; another account cannot inherit its submission identity. Background polls never extend idle expiry or overwrite draft fields/focus. Show stale-count conflicts separately from live availability.

### Records, imports and reporting
- Task-focused missionary profiles show identity, arrival status, mission/language and goods received first, with remaining supported roster details expandable. One selected report at a time uses relevant shared filters across its screen, CSV and PDF, including explicit archived-record state; downloads contain all matching rows, not just one page.
- Group summary totals by stable record IDs and show current names/descriptions; original issue details/history retain snapshots. Date ranges select when issuance happened, using the existing current-net meaning: subsequently undone issues remain excluded. Label this clearly; it is not a frozen historical balance or movement-date accounting. Available-stock reports always describe stock now.
- PDFs use A4, wrapped cells/repeating headings, appropriate embedded licensed font coverage and real rendered/export checks for long descriptions and Māori macrons/accents. Keep formula-safe CSV and lossless versioned full bundles; do not change account/secrets exclusions or imply bundles are recovery backups.

Track uploaded field presence, correctly save dates on new records and require re-upload of old previews whose semantics cannot be established. Retain header aliases, bounded parsing, row approval/ownership/TTL/revision safeguards and wholly valid administrator replacements that archive missing records. Preview changes in plain language.
- Administrator account/settings/reauth screens use the same form/error system. Every sensitive route, including aliases, requires the same recent-password protection. Settings changes and audit records share an atomic maintenance-guarded service. Never retain passwords in error recovery. Keep migration/reset tools separate, with existing typed confirmation, backup and maintenance protections. Refresh existing in-app guide and synthetic images, not a separate presentation package.

## Decisions and why

- **Canonical task frames inside native dialogs (07):** short inventory edits reuse bound Django pages and the same safe-form serializer, with validated list returns, dirty/pending-close guards and restored focus/scroll. Forms stay hidden until deferred recovery/completion handlers are ready; blocked expired-session loads retain a usable Cancel/full-page fallback. Only the task GET/edit views allow `SAMEORIGIN`; global framing protection stays `DENY`. Same-user recovery repairs both frame and parent-shell CSRF. Reject a competing client mutation path or putting long forms/imports/batches into universal modals.
- **Portable audit-backed batch receipts (07):** a fingerprint, actor and created item IDs in an ordinary audit event provide exact deliberate retries inside the existing IMMEDIATE transaction. Each item still uses the canonical opening-ledger/audit service. Reject partial saves, changed-payload reuse and a new draft/schema/ZIP subsystem for this bounded 50-row operation.
- **Unicode-folded local matching (07):** SQLite's default case-insensitive matching is ASCII-only; a connection-local deterministic fold function gives Māori-capable term/exact matching shared by lists and finders. Reject an external index, fuzzy substitutions or a data migration for this scale. Client catalogue ordering remains stable and explicit recipient UUID selection is required.

- **Professional redesign, not another CSS reskin (07):** user rejected current controls/navigation/copy and approved a new issuing study. Preserve capabilities and tested invariants, reject keeping old page structure for familiarity or rewriting the backend for appearance.
- **Rebuilt sidebar and global/local search (07):** user chose concept B over top navigation and both search scopes. Make History direct and issuing prominent; reject crowded utility links and search-plus-select duplication.
- **Mixed panels/full pages (07):** user chose short tasks in context with retained list state; longer forms need full pages. Reject universal modals or reliability sacrificed for fewer page transitions.
- **Atomic multi-item creation (07):** user explicitly included the original batch convenience. Reject duplicate overrides/partial saves; preserve normalized identity, ledger, audit and maintenance safeguards.
- **Tailored Reftab/Church-inspired experience (07):** use references for consistency/tone, not enterprise feature sprawl, copied site architecture or unapproved assets. Keep the existing stack and bundled components.

- **Public prebuilt images over private registry downloads (2026-10-13):** the user approved public application distribution to remove installer accounts/tokens. This supersedes the original private-image choice, not the LAN-only deployment or data/privacy protections. Keep version pins and controlled updates; reject distributing live databases, backups, credentials or the private source HTML.
- **Page-owned uncertain recovery over competing safe-form submissions (review follow-up):** a second AJAX response can replace main content and erase another form's retained request/key. Serialize safe-form writes until the active request has a definitive outcome; permit only its deliberate retry while uncertain and warn before abandoning it. Retain the current GET URL on rejected action POSTs, and repair shell CSRF during same-user recovery. Reject allowing concurrent whole-page responses to destroy pending state; no persistent draft/queue is introduced.
- **Canonical spreadsheet headers before aliases (review follow-up):** exports include internal `id` and canonical `external_id`; canonical headers win regardless of order, while legacy aliases remain fallbacks. Reject first-column matching that changes a roster identity during export/re-import.

- **One overhaul milestone over four deliverables:** the user wants one finished app. Keep ordered safety, UI, completion and validation phases within one bounded plan; use small reviewable implementation commits instead of a big-bang rewrite.
- **Task-led structure over prototype navigation:** explicitly approved redesign makes five staff destinations and contextual tools clearer; reject retaining the old layout merely for familiarity. Keep Home as the user-selected landing, not automatic entry into issuing.
- **One issuing workspace over a multi-screen wizard:** frequent staff work benefits from a visible recipient/list/summary without extra navigation. A 50-distinct-item bound, delegated to the planner, avoids the old arbitrary ten-row limitation while bounding requests. Recipient changes clear drafts after confirmation rather than silently reuse another person's order.
- **Open-tab recovery over saved drafts/offline synchronization:** the user chose predictable, temporary drafts without persistent personal browser data or additional server draft ownership/retention. Closing/reloading loses them; deliberate same-user recovery must not replay writes.
- **Task-focused profiles over showing every field upfront:** the user chose useful issuing context first and expandable details, with complete supported edits rather than hidden or discarded roster information.
- **Safe import blanks over implicit clearing:** the user chose preservation for both modes; field clearing requires an explicit edit. Missing columns and blanks cannot erase data, while replacement still archives missing records.
- **Stable-ID/current-net summaries over historical-name fragmentation or period accounting:** the user chose current identities and existing net semantics; history retains exact snapshots. Shared filters prevent screen/download disagreement; stock now is never presented as as-of stock.
- **Consistent accessible product over a cosmetic reskin or new stack:** retain the tested monolith and improve supporting forms/components/JS, all screens and real failure states. No imposed theme or extra boss-facing package; use actual behavior and rendering evidence rather than screenshots or file headers alone.
- **Shared bound forms and explicit in-memory retries (milestone 06):** keep safe record/count/settings/undo input through validation, maintenance and same-user recovery. Refresh CSRF with a read-only, no-activity session endpoint; never store or replay a draft. Freeze uncertain requests and retry their original payload/key deliberately rather than modifying a request that may already have committed. Account forms never repopulate passwords; POST-only privileged actions return to their GET screen for deliberate resubmission.
- **Bundled Noto Sans and labeled wide PDF records (milestone 06):** use unmodified SIL-OFL Noto Sans for local UI and embedded Unicode PDF text, rejecting base Helvetica/Vera because macrons are missing. Summary tables wrap and repeat headings on portrait A4; wide history/record exports use labeled Field/Value blocks on landscape A4 rather than illegible columns. CSVs remain complete and formula-safe. Test-only native PDF rendering runs in an isolated subprocess with checked exit status, avoiding a Python 3.13/Django/native-finalizer crash without suppressing renderer failures; it is not shipped in the image.

- **Remediate and independently re-review instead of shipping on green contract tests:** live probes demonstrated data-loss and operational failures. Keep Django/SQLite/Compose, fix all findings with regressions, then search for additional issues before release approval. User requested all review fixes in worktree-portable plans; implementation must not rely on the ignored report.

- **Modular monolith over patching the HTML or microservices:** preserves workflows while replacing tangled persistence and centralizing inventory correctness, without service sprawl.
- **Django/templates over React plus a separate API:** built-in identity/migrations and fewer independently maintained components suit this temporary single-host tool.
- **SQLite over PostgreSQL:** adequate for ten users and one writer-owning server, simpler recovery/operations; revisit if multi-server or sustained contention is needed.
- **Local accounts over Microsoft/SMTP dependencies:** no paid Microsoft services are available; administrators handle provisioning/recovery.
- **Ledger, stable IDs and retained history over overwritten totals/name joins:** support concurrent correctness, corrections and the eventual migration.
- **Explicit partial fulfillment over silent reduction or blanket rejection:** staff can finish available work but must confirm the revised list.
- **Single roster and staff attribution over multi-intake/signature expansion:** preserve the requested scope without adding unused features.
- **ZIP/CSV manifest over opaque database interchange:** portable and inspectable for Power App migration while representing complete relationships; backups remain the recovery source.
- **Compose/prebuilt images over on-host builds or OS-specific installers:** consistent deployment and controlled remote updates. Image visibility is now public as recorded above.
- **LAN HTTPS/self-issued certificates over public hosting:** matches available infrastructure; trust warnings and host controls remain explicit operational limitations.
- **Guided everyday workflows over exposing technical controls:** nontechnical staff need plain language, progressive disclosure and a short guide; operational complexity stays with the operator. Certificate trust configuration is deferred by user request, while HTTPS remains required.
- **Immediate transactions plus bounded retry of transient SQLite locks (milestone 01):** WAL and `BEGIN IMMEDIATE` serialize writers, but contended writers can still see transient `database is/table locked` errors; write services retry the whole atomic block a bounded number of times so the loser re-reads fresh state and raises the proper domain error (shortage, stale version, already-reversed) instead of a raw database error.
- **Owned exclusive maintenance windows over a shared boolean flag (milestone 05):** a second operator's acquisition fails instead of sharing or clearing another window; same-owner nesting counts depth so inner blocks cannot reopen outer work; exits require the entry token; crashed windows stay closed until an explicit audited force-takeover. File-level backup/restore still needs the operator to stop writers (scripts do), because SQLite has no cross-process write barrier.
- **Atomic manifest-recorded backups with verified-only protection (milestone 05):** temporary file + fsync + rename plus a JSON manifest (path/checksum/version/schema/completion) distinguishes verified backups from interrupted copies; the protected recovery backup is the newest *verified* file, so corrupt files can never supersede protection. Verification also enforces 0600 permissions and refuses backups from newer code.
- **Exact import revisions and owned single-use previews (milestone 05):** the revision token hashes every record's id/version so lower-version edits invalidate previews; confirmation re-checks inside the write transaction while holding a row lock, enforces creator-or-admin ownership, 24-hour TTL and single use. Unchecked-all means none, never all.
- **DB-backed throttle buckets over cache counters (milestone 05):** login and re-authentication share atomic `select_for_update` buckets so concurrent failures across Gunicorn workers count exactly; re-auth confirmations bind user id plus password hash and cycle the session key.
- **WhiteNoise static serving plus Caddy default_sni (milestone 05):** Gunicorn serves its own collected static files so TLS delivery does not depend on proxy file-serving; `default_sni` serves the site certificate to IP-literal clients (real browsers send no SNI for IPs) — verified by a live HTTPS probe that failed before the fix.
- **Lossless source mapping over row-count equality (review fix):** the six original roster keys (`arrived/homeStake/missionArrival/missionRelease/tLanguage/type`), `remain`/threshold/Stock-Out variants and `intake_metadata` are mapped and round-tripped through converter/models/bundles; unparseable dates survive as `*_raw` metadata. Row counts never prove fidelity.
- **Canonical image pin over bare IMAGE fallback (review fix):** `IMAGE_BASE` (or legacy `IMAGE`) is a tagless repository; `VERSION` always supplies the tag (`IMAGE_BASE:VERSION` == `APP_VERSION`). Tagged bases are refused; successful updates/restores atomically persist `VERSION` so later plain Compose cannot revert. Proven by real `compose config` JSON for two releases, not strings.
- **Loopback-allowed probes over wildcard hosts (review fix):** production keeps a LAN-only `DJANGO_ALLOWED_HOSTS`; the app additionally allows only `127.0.0.1`/`localhost`/`app` so container readiness gates see real state instead of 400, without `*`.
- **Initialized verify plus audited takeover over bare python-c and blind clears (review fix):** `verify_backup` runs with Django setup; `restore_db --force-takeover` and script `--takeover` take over explicitly (audited, writes stay closed, WAL-safe offline restore, preserved copy, readiness before reopen), re-recording the audit after the file swap so it survives.
- **Snapshot exports plus ordered chains over aggregate sums (review fix):** exports read in one transaction with a ledger gate and retry; bundles validate deterministic `(created_at, id)` chains (single leading OPENING, directions, running balances, no historical negatives). Reversal attribution is a durable snapshot surviving renames/deletes/re-imports without accounts.
- **Host-only backups over external backup infrastructure for now:** accepted initial constraint, not protection against host loss.
